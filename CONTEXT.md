# AI Content Studio — Domain Glossary

> Use these terms **exactly** in code, tests, commits, and conversation. If you encounter an undefined term during a session, add it here.

---

## Business Domain

| Term | Definition |
|------|-----------|
| **Business Profile** | The onboarding data a user provides: business type, products/services, target customers, brand identity. Stored in the `business_profiles` table. Drives ALL generation. |
| **Business Type** | Industry category: `restaurant`, `e-commerce`, `salon`, `gym`, `real_estate`, `fashion`, `freelancer`, `other`. Determines content templates and recommended posting schedules. |
| **Brand Kit** | The visual and verbal identity: colors (hex codes), tone (`professional` / `casual` / `playful` / `luxury`), logo URL, font preferences. Extracted from onboarding + logo upload. |
| **Content Calendar** | Auto-generated weekly/monthly schedule of planned content. Each slot specifies: date, time, platform, content type, and associated Asset Kit. |
| **Asset Kit** | A complete, ready-to-publish content unit: image or video + caption + hashtags + platform metadata. The atomic output of the generation pipeline. |
| **Media Library** | A user's own uploaded business photos (storefront, products, team), stored in R2 and recorded in `media_library` (`src/lib/media-library.ts`, STU-C3). `source` = `upload` (user) or `generated` (app-produced). Provides real source material for image-to-image pipelines — the product-photo "upload" step and the before/after composite (STU-C4) — instead of relying only on text-to-image generation. Distinct from the **Gallery**, which shows generated Asset Kits. |
| **Content Slot** | A single position in the Content Calendar (e.g., "Monday 10am Instagram Post"). Gets filled with an Asset Kit. |
| **Content Type** | Category of content: `product_showcase`, `tip`, `behind_the_scenes`, `promo`, `testimonial`, `ugc_ad`, `seasonal`, `engagement`. |
| **Industry Template** | Pre-configured generation settings per Business Type. E.g., restaurant template emphasizes food photography + daily specials; gym template emphasizes motivational graphics + class promos. |

## AI / Generation Domain

| Term | Definition |
|------|-----------|
| **Agent Loop** | The core generation pipeline: **Plan → Retrieve → Route → Execute → Assemble → Publish**. Orchestrated by the Next.js backend. |
| **Plan Step** | AI analyzes the Business Profile + Content Slot → determines what content to create (content type, visual style, copy angle). |
| **Retrieve Step** | Queries the Brand Knowledge Base (pgvector) for relevant context chunks. Ensures brand-consistent output without dumping the entire profile into every prompt. |
| **Route Step** | Model Router selects the optimal Muapi model for each asset based on type, quality, cost, and speed. |
| **Execute Step** | Parallel API calls to Muapi (visual assets) and OpenAI (text assets). |
| **Assemble Step** | Combines generated media + text into a complete Asset Kit. Uploads media to R2, saves metadata to DB. |
| **Publish Step** | Optionally pushes the Asset Kit to YouTube / TikTok / Instagram via Muapi's social publishing API. |
| **Model Router** | Decision logic mapping asset types to AI models. E.g., product photo → `ai-product-shot`, social graphic → `nano-banana-2`, UGC video → `creatify-lipsync`. Implemented in `src/lib/model-router.ts` as a config-driven table (DEV-18). Hardened against catalog drift in STU-C1. |
| **Asset Type** | The kind of media the Model Router routes to a Muapi model. Canonical values (`src/lib/model-router.ts`): `product_photo`, `social_graphic`, `text_graphic`, `video_animate`, `ugc_lipsync`, `voiceover`, `video_assemble`, `video_reframe`, `background_removal`, `reframe`. Distinct from **Content Type** (the editorial category of a post). |
| **Text-Graphic** | An Asset Type (`text_graphic`) for text-heavy graphics where the copy itself must render legibly — daily specials, sales/promos, class schedules, market updates, booking promos, testimonials/quotes, tips, motivation posts. Routed to text-rendering specialists (`nano-banana-2` standard — repointed 2026-07-23 off the dead `ideogram-v3-t2i` / `nano-banana-pro` premium), not the general graphic models. Generated by `src/lib/text-graphic.ts` (STU-C2): the prompt quotes the exact display text with legibility/layout guidance. |
| **Before/After Composite** | A single side-by-side image built from **two** of the user's own Media Library photos (a "before" and an "after"), each scaled to a common height and labelled ("BEFORE"/"AFTER" by default), saved as an Asset Kit. Serves salon/gym transformation posts (before & after, style/member results). Built by `src/lib/composite.ts` (STU-C4) with `sharp` — a **$0, no-model-call** operation (decode → resize → stitch → burn in SVG label bands). An optional `nano-banana-edit` enhancement pass is an off-by-default injectable seam. Invoked via `POST /api/composite` with two Media Library item ids (ownership-scoped). |
| **Carousel** | An Asset Kit that carries an **ordered array of image frames** (`asset_kits.media`, jsonb) instead of a single image, all sharing one caption/hashtag set — how-to guides, process breakdowns, style guides, lookbooks. The frames come from the existing generation pipelines (photo/graphic/text-graphic); `src/lib/carousel.ts` (STU-C5) is the multi-image Assemble step: it downloads each frame in order → uploads to R2 → saves one kit whose `media` order is the source of truth. The cover (`mediaUrl`/`mediaType`) mirrors frame 0 so single-image consumers (gallery thumbnails) are unaffected; an empty `media` array means a plain single-image kit. Frame count is bounded `[2, 10]` (`CAROUSEL_MIN_FRAMES`/`CAROUSEL_MAX_FRAMES`; 10 = Instagram's carousel limit). Invoked via `POST /api/carousel`. **Phase-4 flag:** Muapi's Instagram publish endpoint must be confirmed to support carousel posts before scheduled carousel publishing is promised. |
| **Presenter** | A stock on-camera person the agent can use for UGC-style video ads (Phase 3 lip-sync). Each has `id, name, imageUrl, gender, ageRange, style, targetAudienceTags[]`. The roster is static data in `src/lib/presenters.ts` (STU-C7, JSON-only MVP — no DB table this slice, following the TS-data convention). DESIGN §9.6: the agent pre-selects the best-matching presenter for the brand's audience; the user can change it. |
| **Presenter Library** | The catalogue of all Presenters, browsable at `/presenters` and filterable by **Audience Tag** (STU-C7). The foundation the Phase-3 lip-sync pipeline and the "agent pre-selects presenter" step consume — **without it Phase 3 cannot run**. Portraits are currently self-contained SVG placeholders in `public/presenters/` (reproducible via `scripts/seed-presenter-placeholders.mjs`); real rights-cleared, lip-sync-ready portraits are a Phase-3 carryover. |
| **Audience Tag** | A coarse brand-audience descriptor a Presenter reads well for (`young-professionals`, `families`, `students`, `fitness-enthusiasts`, `beauty-wellness`, `luxury-shoppers`, `trend-followers`, `homeowners`, `entrepreneurs`, `foodies`). Presenters carry the tags that fit them; the Presenter Library filters on ANY selected tag (union), and Phase 3 matches them to the business's audience. Canonical list = `AUDIENCE_TAGS` in `src/lib/presenters.ts`. |
| **Quality (Route Tier)** | The Model Router tier chosen per asset: `standard` (fast/cheap) or `premium` (higher quality). Invisible to users. |
| **Model Catalog** | Muapi's live list of models (`GET /api/v1/models`, public/no-key), fetched + ~1h cached by `src/lib/muapi-catalog.ts` (STU-C1). Source of live per-model cost and `category`. The Model Router overrides its stale hard-coded costs from here and fails loud when a routed model has vanished from it. |
| **Input Type** | What a generation UI must ask the user to supply for an asset type: `text`, `image`, or `text+image`. Derived from the model's catalog `category` ("Text to X" → text, else image). Exposed per routing entry (STU-C1). |
| **Liveness Canary** | `pnpm canary:muapi` (`scripts/muapi-canary.ts`, STU-C1) — POST-probes every routed model to distinguish catalog-listed from actually-live endpoints (`404` = dead, `422`/`400` = live). Catalog presence ≠ liveness ≠ completion; see `.agents/memory/muapi-api-contract.md`. |
| **Generation** | One invocation of an AI model producing one output (one image, one video clip, one text block). The atomic billing unit. |
| **Generation Credit** | Internal unit tracking AI usage per user per billing period. One generation = one credit. Different asset types may cost multiple credits. |
| **UGC Pipeline** | The 5-step User-Generated Content video pipeline: script → voiceover → lipsync → B-roll → assembly. Produces a talking-head style product review video at ~$0.91. |
| **UGC Script** | The ~15-second first-person spoken script for a UGC video ad, written by the agent (GPT-4.1-mini) from a product + brand context via RAG (DEV-27, `src/lib/ugc-script.ts`). Returned as three timeline segments — `hook` (talking head ~0-8s), `body` (voiced over B-roll ~8-12s), `cta` (talking head ~12-15s) — plus `spokenText` (the ordered concatenation the voiceover step consumes) and `wordCount`/`estimatedSeconds` reported against the 15-second budget (~2.5 words/sec, not hard-truncated). |
| **UGC Voiceover** | The natural-speech audio track (MP3) for a UGC video ad, generated from the **UGC Script**'s `spokenText` via Muapi's `gemini-3-1-flash-tts` (Asset Type `voiceover`, DEV-28, `src/lib/ugc-voiceover.ts`). Single-speaker request shape `{ speakers: [{ speaker_id, voice_name, accent, style, pace }], dialogue_turns: [{ speaker_id, text }], temperature? }`; `voice_name`/`accent`/`style`/`pace` are enums from the model's live input-schema (`VOICEOVER_VOICES` = 30 Gemini voices, default `Kore`). The audio URL feeds the lip-sync step (DEV-29). **Swapped 2026-07-24** off `elevenlabs-text-to-dialogue-v3` (failed 7/7 in practice); `gemini-3-1-flash-tts` completes at ~$0.003 and is end-to-end verified. |
| **UGC Talking Head** | The lip-synced talking-head video for a UGC ad, generated from a **Presenter** portrait + the **UGC Voiceover** audio via Muapi's `infinitetalk-image-to-video` (Asset Type `ugc_lipsync`, DEV-29, `src/lib/ugc-lipsync.ts`). Request shape `{ image_url, audio_url, resolution, prompt? }` (`resolution` enum `480p`/`720p`, default `480p`). The video URL feeds the assembly step (DEV-32). **Swapped 2026-07-24** off the plan's `creatify-lipsync`: the live schema showed it — and every $0.04 lip-sync model (latent-sync/sync-lipsync/veed-lipsync) — is an *Audio-to-Video* model requiring a presenter *video* (`video_url`), so it can't animate a static portrait; `infinitetalk-image-to-video` (image+audio, ~$0.28) is the plan's real intent and is completion-verified end-to-end. |
| **UGC B-roll** | The short animated product clip intercut into a UGC ad (the ~8-12s middle slot), generated from a product photo via Muapi's `kling-v2.1-standard-i2v` (DEV-30, `src/lib/ugc-broll.ts`). Reuses the existing `video_animate` **Asset Type** (which already routes to that model — standard / `kling-v2.1-pro-i2v` premium) rather than adding a duplicate type. Request shape `{ prompt, image_url, aspect_ratio, duration }` — `prompt` (motion guidance, defaults to `DEFAULT_MOTION_PROMPT`) and `image_url` required; `aspect_ratio` enum `16:9`/`9:16`/`1:1` (default `16:9`, the talking-head orientation the DEV-31 reframe derives from); `duration` enum `5`/`10`s (default `5`). Completion-verified end-to-end (real product image → real MP4, ~75s, **$0.225**). The clip feeds the assembly step (DEV-32). |
| **UGC Assembly** | The step that stitches the ordered UGC clips (**UGC Talking Head** → **UGC B-roll** → talking-head CTA) into one master video via Muapi's `video-combiner` (Asset Type `video_assemble`, DEV-32, `src/lib/ugc-assembly.ts`). Request shape `{ videos_list, aspect_ratio? }` — `videos_list` an ordered array of 2–20 clip URLs (each 5–60s); `aspect_ratio` enum `auto`/`16:9`/`9:16`/`1:1`/`4:3`/`3:4`/`21:9`/`9:21` (default `auto` = the first clip's ratio). The service is a generic assembly primitive: the caller supplies the ordered clips; *which* clips is the pipeline orchestrator's job. `video-combiner` is the plan's **primary** assembly path (chosen to avoid the FFmpeg-on-Replit risk); server-side FFmpeg is the documented fallback. The master video URL feeds the reframe step (DEV-31). ⚠️ **Live completion NOT yet verified** — the model was provider-side saturated (503 "at capacity") for ~20h during the build; the endpoint/key/schema are confirmed correct and the probe must be re-run before final sign-off. |
| **UGC Reframe** | The step that crops+reframes the **UGC Assembly** master video into the platform aspect ratios — 9:16 (TikTok / Reels / Shorts), 1:1 (feed), 16:9 (landscape) — via Muapi's `autocrop` AI subject tracking (Asset Type `video_reframe`, DEV-31, `src/lib/ugc-reframe.ts`). Request shape `{ video_url, start_time, end_time, aspect_ratio? }` — `aspect_ratio` enum `9:16`/`16:9`/`1:1`/`4:5`/`4:3`/`3:4` (default `9:16`); `start_time`/`end_time` are the whole-second crop window (defaults 0 / 60, `end > start`). The service is a single-reframe primitive (`reframeVideo`) plus a `reframeToFormats` fan-out that produces the plan's default 9:16/1:1/16:9 set + summed cost; *which* formats and R2 persistence into a multi-format Asset Kit are the pipeline/DEV-33 orchestrator's job. Distinct new Asset Type from the image `reframe` (`ideogram-v3-reframe`, used by DEV-19 product photos): `autocrop` is a video→video op. **Model-corrected** (2026-07-10, plan) off `luma-flash-reframe` ($0.35, 7× the cost) — kept as the documented manual premium fallback (different schema, no segment window) if subject tracking fails. The three reframed variants feed the R2 upload / Asset Kit step (DEV-33). |
| **UGC Job** | One end-to-end UGC video build, stored in the `ugc_jobs` table (DEV-33, `src/lib/ugc-pipeline.ts`). Mirrors a **Content Plan**: the agent proposes a **UGC Script** + a pre-selected **Presenter** (a `draft` job); the user reviews/edits; then the pipeline runs step-by-step (`generating` → `completed`/`failed`). The per-step status list **and** each step's intermediate output URL live on the row, so a failed step *resumes* from where it stopped rather than restarting the 2–5 min pipeline (the AC's "retry from that step"). Steps: voiceover → talking head → B-roll → assembly → reframe → finalize; B-roll + assembly appear only when the user has a Media Library photo to animate (talking-head-only otherwise). The three reframed variants finalize into one multi-format video **Asset Kit** (the Carousel `media[]` pattern). Orchestrated by `UgcPipelineService` (`propose` + `run`, injectable step seams like `generation-queue.ts`); driven by the `/api/ugc` routes. |
| **UGC Review UI** | The agent-driven UGC wizard at `/plan/ugc` (DEV-33, DESIGN §9.6): propose → review script (editable) + presenter (changeable) → confirm ("3 credits") → step progress with friendly labels → result (video with per-format 9:16/1:1/16:9 tabs + downloads). No prompts, model names, or dollar costs. "Publish Now" / "Add to Calendar" render disabled ("coming soon") until connected accounts (Phase 4/5) and the calendar exist. |
| **B-Roll** | Secondary video footage (animated product photo) intercut with the main talking-head video. Adds visual variety to UGC ads. |
| **Brand Conditioning** | The practice of injecting **retrieved** Business Profile context (via RAG) into every AI prompt to ensure brand-consistent output. Uses the Brand Knowledge Base, not raw profile dumps. |
| **Asset** | A single generated file: one image, one video, or one audio clip. Multiple assets combine into an Asset Kit. |
| **Content Plan** | A proposed set of 5-7 content items for a given week, generated by the agent based on Business Profile + RAG context + industry best practices. User reviews, edits, and approves. Stored in `content_plans` table with status: draft → approved → generating → completed. |
| **Content Plan Item** | One entry in a Content Plan: `{ type, title, description, platform, scheduledDay, estimatedCredits }`. Becomes a calendar entry and Asset Kit after generation. |
| **Generation Queue** | The system that processes an approved Content Plan: iterates through items, calls the Agent Loop for each, tracks per-item status (pending → generating → completed → failed), enables parallel execution for images. |
| **Presenter** | A stock photo of a person used as the talking head in UGC videos. The agent pre-selects based on brand audience. User can change but doesn't have to. Replaces "avatar" to avoid confusion with user profile avatars. |
| **Prompt Template** | A parameterized prompt string with placeholders for Business Profile data. E.g., `"Create a {brandTone} Instagram post for a {businessType} featuring {productName}"`. |
| **Credits Display** | All credit usage shown to users as "X of Y left" (e.g., "15 of 50 remaining"). Never as dollar amounts, never as model names. Users see usage, not infrastructure. |
| **Industry Strategy** | A per-business-type content playbook. **Canonical source: `src/lib/industry-templates.ts`** (`INDUSTRY_TEMPLATES`, a TS module — not a `data/industry-strategies.json`; STU-C6 chose one typed source of truth over a parallel JSON). Defines the recommended posting cadence + weekly content-type mix, plus a one-line `strategyHint` string. All fed into the ContentPlannerService prompt; falls back to the `other` template for unlisted types. |
| **Seasonal Calendar** | Region-aware fixed-date holidays in **`src/lib/seasonal.ts`** (a TS module — not a `data/holidays.json`; STU-C6 decision). A `GLOBAL` set of broadly-observed occasions is merged per **Region** via `holidaysForRegion(region)`. `upcomingHolidays(now, windowDays, region = "US")` returns those within a window (default 21 days), nearest-first. The ContentPlannerService injects them into the GPT prompt so it themes content around what's coming. |
| **Region** | The market whose seasonal calendar applies to a business (`Region` = `US \| UK \| CA \| AU` in `seasonal.ts`; STU-C6). Passed into `upcomingHolidays`/`proposePlan` as an optional parameter defaulting to `US`. The Business Profile has **no region column yet** (deferred to a later slice) — `PlannableProfile.region` is the forward-compatible seam the API route will fill once it exists. |
| **Business Events** | User-defined milestones stored in `businessProfile.businessEvents` as `{ name, date, recurring }`. Examples: "Anniversary Sale, March 5, yearly" or "Summer Collection Launch, June 15, one-time". Captured during onboarding Step 6. |
| **Performance Feedback Loop** | The system where user feedback (thumbs up/down, regeneration rate, caption edit rate) is aggregated by `AgentEvalsService.getPerformanceInsights()` and fed back into `ContentPlannerService.proposePlan()` to bias future plans toward content types the user's audience prefers. |
| **Agent Eval** | Automated quality checks on the agent's output. Includes: `scorePlanQuality()` (0-100 score, auto-regenerate below 60), pipeline reliability metrics, and user feedback aggregation. Data stored in `generation_feedback` and `pipeline_logs` tables. |
| **Pipeline Log** | A row in the `pipeline_logs` table recording one step of a generation pipeline: step name, model used, duration_ms, success/failure, error message, cost. Used by `AgentEvalsService.getPipelineReliability()` and surfaced in the Admin panel (Phase 7). |
| **Plan Quality Score** | A 0-100 score computed by `scorePlanQuality()` before showing a proposed plan to the user. Checks: platform coverage, content type diversity, product rotation, seasonal relevance. Plans scoring below 60 are silently regenerated. |

## RAG / Knowledge Base Domain

| Term | Definition |
|------|-----------|
| **Brand Knowledge Base** | A per-user semantic vector store (pgvector on Neon) containing embedded representations of all brand data: products, brand guidelines, past generations, user edits, and industry knowledge. Queried during the Retrieve step of the Agent Loop. |
| **Embedding** | A 1536-dimensional numerical vector representation of a text chunk, generated by OpenAI `text-embedding-3-small`. Stored in the `brand_embeddings` table. Cost: ~$0.02 per 1M tokens (essentially free). |
| **Retrieve Step** | The second step in the Agent Loop (Plan → **Retrieve** → Route → Execute → Assemble → Publish). Queries pgvector with the generation request to find the most relevant context chunks for that specific generation. |
| **Cosine Similarity Search** | The vector search algorithm used to find embeddings most similar to the query embedding. pgvector provides this via the `<=>` operator. Returns top-k results ranked by relevance. |
| **Context Chunk** | A single piece of retrieved text from the Brand Knowledge Base (e.g., one product description, one brand guideline paragraph, one past caption). Multiple chunks are assembled into the prompt context. |
| **Auto-Embedding** | The automatic process of embedding new data into the Brand Knowledge Base. Triggered on: onboarding completion, product create/update, generation completion, user caption edits. The system learns from every interaction. |
| **pgvector** | PostgreSQL extension for vector similarity search. Enabled on Neon with `CREATE EXTENSION vector`. Stores embeddings as `vector(1536)` columns and supports cosine distance indexing. |
| **top-k** | The number of most-relevant context chunks retrieved per query. Default k=8. Higher k = more context but higher token cost and potential noise. |

## Social Publishing Domain

| Term | Definition |
|------|-----------|
| **Connected Account** | A user's linked social media account (YouTube channel, TikTok account, Instagram Business account) authorized via OAuth through Muapi. |
| **Social Account** | The persisted representation of a **Connected Account** — one row in the `social_accounts` table (DEV-35, `src/lib/social-publishing.ts`): `platform`, `muapiAccountId`, `platformName`, `accountName`, `connectedAt`. The connection flow: `getConnectUrl` → the user completes OAuth → Muapi captures the token (we store **none**) and bounces the browser to our `/api/social/callback` → `syncAccounts` fetches the user's accounts from `GET /social/ext/accounts` and upserts them (idempotent on `user + muapiAccountId`). Surfaced at `/social` (DESIGN §9.9) where each account can be **renamed** (a local nickname — DEV-34) or **disconnected** (Muapi revoke + local delete — DEV-34). `platform` is stored as the string enum `youtube`/`tiktok`/`instagram` (see **Platform ID**). |
| **Account Nickname** | An optional user-set friendly label on a **Social Account** (`social_accounts.nickname`, nullable — DEV-34). "Rename" in the accounts UI sets this local label only; you can't rename a real platform handle via API. Display name = `nickname ?? accountName`; a blank nickname clears it. Preserved across OAuth re-sync (`syncAccounts` never writes it). Edited via `PATCH /api/social/accounts`; max 60 chars. |
| **external_user_id** | The Clerk user ID passed to Muapi when connecting social accounts. Scopes OAuth tokens per end-user in the multi-tenant model. |
| **account_id** | Muapi's internal identifier for a connected social account. Integer, returned from the accounts API. Used in all publish calls. |
| **Connect URL** | A one-time OAuth URL generated by Muapi (`POST /api/v1/social/{platform}/connect-url`). Sent to the user's browser to authorize posting. |
| **Publish Job** | An async social publishing request. Returns a `request_id`. Status checked via polling (`GET /api/v1/predictions/{id}/result`) or webhook. |
| **Platform ID** | Muapi's numeric platform identifier: YouTube = `1`, TikTok = `2`, Instagram = `3`. ⚠️ **Our `social_accounts.platform` column stores the string slug enum (`youtube`/`tiktok`/`instagram`), not these numbers** (DEV-35 decision — matches every other schema enum + the Muapi endpoint slugs). The `1/2/3` mapping is only Muapi's own; map at the boundary if a publish call ever needs it. |

## Billing Domain

| Term | Definition |
|------|-----------|
| **Plan Tier** | Subscription level. Tentative: Free, Starter ($19/mo), Pro ($49/mo), Business ($99/mo). Each tier has different generation limits and feature access. Final pricing TBD after computing server costs. |
| **Generation Limit** | Maximum generation credits per billing period per plan tier. |
| **Usage Meter** | Real-time counter of generation credits consumed in the current billing period. Displayed in the dashboard. |
| **Billing Period** | Monthly cycle starting from subscription creation date. Credits reset at period start. |
| **Overage** | When a user exceeds their generation limit. Behavior TBD: hard block vs. pay-per-extra. |
| **COGS** | Cost of Goods Sold — the Muapi + OpenAI API costs incurred to serve one user. Tracked via `X-MuAPI-Cost-USD` response headers. |

## Technical / Workflow Domain

| Term | Definition |
|------|-----------|
| **Slice** | An atomic unit of work. One Linear issue, one focused change, one checkpoint. Takes 1–4 hours. |
| **Phase** | A group of related slices delivering a major feature. One phase = one PR (or one Replit checkpoint series). |
| **Checkpoint** | A named save point in Replit (equivalent to a git commit). Created after each slice is complete. |
| **Session** | One continuous work period by an agent. Starts with reading protocol files. Ends with PROGRESS.md update + Linear sync. |
| **Session Log** | An entry in PROGRESS.md recording: date, slice worked on, files touched, decisions made, tech debt observed, blockers. Newest entry at top. |
| **Current Status** | The top section of PROGRESS.md. Overwritten each session. Contains: active phase, current slice, next action, blockers, files last touched. |
| **Acceptance Criteria** | GIVEN/WHEN/THEN statements in PLAN.md defining when a slice is "done". Uses RFC 2119 language (MUST, SHOULD, MAY). |
| **ADR** | Architecture Decision Record. Documents a significant technical decision, its context, alternatives considered, and consequences. Stored in `docs/adr/`. |
| **Agent Loop** | (see AI domain) Also used loosely to mean "the generation pipeline" in conversation. |
| **Feedback Loop** | The commands run after every change: `pnpm typecheck && pnpm test && pnpm lint`. |

## Admin Domain

| Term | Definition |
|------|-----------|
| **Admin Panel** | A separate `/admin` route group accessible only to users with `role = 'admin'`. Provides dashboards for users, revenue, costs, and account management. |
| **Admin Role** | A value in the `users.role` column. Values: `user` (default), `admin`. Checked by middleware on all `/admin/*` routes. First admin bootstrapped manually in DB. |
| **MRR** | Monthly Recurring Revenue. Sum of all active subscription prices. Primary revenue health metric. Sourced from Stripe, cross-referenced with `subscriptions` table. |
| **Churn Rate** | Percentage of paying subscribers who cancel per month. Calculated as: (cancellations this month / paying subscribers at start of month) × 100. |
| **Conversion Funnel** | The progression: Free signup → Onboarding complete → First generation → Paid subscription. Each stage tracked via PostHog events. |
| **LTV** | Lifetime Value. Average total revenue per user over their entire subscription lifetime. LTV = ARPU × (1 / churn rate). |
| **ARPU** | Average Revenue Per User per month. Total MRR / total paying subscribers. |
| **Cost Alert** | An admin dashboard flag raised when a user's COGS exceeds the revenue their plan generates. Indicates a money-losing customer. |

| Term | Definition |
|------|-----------|

| **PostHog** | Product analytics platform (Cloud free tier, 1M events/mo). Used inside the authenticated app for: feature usage, funnels, retention, session recordings. |

| **Error Boundary** | A React component that catches JavaScript errors in its child component tree, logs them to Sentry, and renders a fallback UI instead of crashing the page. Every page has one. |

## Email Domain

| Term | Definition |
|------|-----------|
| **Brevo** | Email service provider (formerly Sendinblue). Used for transactional emails, lifecycle drip campaigns, and newsletters. Single vendor for all email. |
| **Transactional Email** | Triggered by a specific user action: welcome email (signup), generation complete, credit warning, payment failed. Sent via Brevo API. |
| **Lifecycle Campaign** | Automated email sequences triggered by user behavior: onboarding nudge (24h after incomplete onboarding), reactivation (7 days inactive), churn prevention (before cancellation). Configured in Brevo workflow builder. |
| **Newsletter** | Product updates and feature announcements sent to all users. Managed via Brevo campaigns. Frequency: monthly or on major releases. |
| **Email Template** | A Brevo template with dynamic variables (user name, product name, etc.). Templates stored in Brevo dashboard, referenced by `templateId` in API calls. |

## Design Domain

| Term | Definition |
|------|-----------|
| **Design Read** | A one-line declaration of page kind + audience + vibe + aesthetic direction. Stated before any UI code is written. See `DESIGN.md` §0. |
| **Three Dials** | Three tunable values that control all design output: `DESIGN_VARIANCE` (layout experimentation), `MOTION_INTENSITY` (animation depth), `VISUAL_DENSITY` (information per viewport). See `DESIGN.md` §1. |
| **The Lila Rule** | Design directive: no AI-purple gradients, no random neon glows. Accent color is Emerald, base is Zinc. See `DESIGN.md` §3. |
| **Asset Kit Preview** | The right panel in the Generate page showing the generated image/video + caption + hashtags. The primary visual output of the app. |
| **Skeleton Loader** | A loading placeholder that matches the exact shape of the final content. Used instead of generic spinners. Required by `DESIGN.md` §7. |
| **Empty State** | A beautifully composed placeholder shown when a list or section has no data. Must include a CTA indicating how to populate. Required by `DESIGN.md` §7. |
