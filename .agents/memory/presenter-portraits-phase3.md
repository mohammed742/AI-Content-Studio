name: Presenter portraits are placeholders — Phase-3 carryover
description: STU-C7 ships the presenter library with self-contained SVG placeholder portraits; real rights-cleared, lip-sync-ready portraits must be sourced before Phase 3's UGC pipeline uses them.

STU-C7 (DEV-64) ships the **Presenter Library** — a static roster of 10 presenters in `src/lib/presenters.ts` (JSON-only MVP, no DB table) browsable + audience-tag-filterable at `/presenters`. This satisfies the slice AC ("presenter list renders ≥8, filterable by audience tags") and unblocks Phase 3 structurally.

**What is NOT real (and must be before Phase 3 uses presenters on camera):** the portrait images. Each presenter's `imageUrl` points at a **self-contained SVG placeholder** in `public/presenters/` (a monogram on a zinc/emerald card), generated by `scripts/seed-presenter-placeholders.mjs`. These are NOT photographs of real people and cannot be lip-synced.

**Why deferred:** sourcing real portraits needs either (a) generating consistent photoreal portraits via a text-to-image model — but the Muapi free-tier shim only completes `nano-banana-2`, and consistent multi-portrait generation is a deliberate one-time task — or (b) licensing stock photos whose license **explicitly covers synthetic-video / lip-sync derivative use** (most do not). Both are out of scope for STU-C7's "list renders + filters" AC.

**How to apply:** In the first Phase-3 UGC slice, before wiring the lip-sync pipeline to a presenter:
1. Source ~8–12 rights-cleared photoreal portraits (prefer generated — unambiguous rights; if stock, verify the synthetic-video derivative clause).
2. Upload them to R2 and repoint each presenter's `imageUrl` at the R2 URL (the roster shape in `presenters.ts` does not change).
3. Delete the `public/presenters/*.svg` placeholders + the seed script once real portraits land.
Do **not** ship the lip-sync flow pointed at the SVG placeholders. See also [[carousel-publish-phase4.md]] (same "verify before you promise" pattern).
